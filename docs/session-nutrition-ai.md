### Invalid Date في التقرير
- **السبب:** كان التاريخ يُخزّن كنص عربي `new Date().toLocaleDateString('ar-TN')` ثم يُعاد تحليله بـ `new Date()` فيفشل
- **الحل:** تخزين ISO string وعرضه بتنسيق تونسي في صفحة التقرير:
  ```javascript
  const MONTHS_TN = ['جانفي','فيفري','مارس','أفريل','ماي',...]
  formatDate(isoStr) → "31 ماي 2026"
  ```

### الأطعمة الممنوعة لا تعمل
- **السبب:** الكود كان يُصفّي العناصر فقط، لكن عدد الوحدات يبقى كما هو
- **الحل:** إضافة `isGroupAvoided()` تكشف إذا كتب المستخدم اسم مجموعة كاملة ("حليب"، "خضر") وتضع عدد وحداتها صفراً وتعيد توزيع السعرات على النشويات

### الزبدة والعسل لا تظهر في الفطور
- **السبب:** لم تكن موجودة في قاعدة بيانات الأطعمة أصلاً
- **الحل:** إضافتهما لمجموعة الدهون مع `meal: 'B'` (فطور فقط)

### الجوز يظهر في الغداء
- **السبب:** كان له `meal: 'BSD'` والحرف 'D' يُفسَّر كـ Dinner/Lunch
- **الحل:** تغييره إلى `meal: 'BS'`

### خطأ client-side exception في صفحة الحاسبة
- **السبب الأول:** `Info` icon مُستخدمة في JSX لكن لم تُضاف للاستيراد من lucide-react
- **السبب الثاني:** `setAiError(null)` مُستدعاة لكن المتغير غير معرّف
- **الحل:**
  ```javascript

  onClick={() => { setForm(INIT); setRes(null); setAiError(null) }}
  
  // بعد
  import { ..., Info } from 'lucide-react'
  ```

## 2. ما تم بناؤه

### محرك التغذية v2 — `lib/nutritionEngine.js`

محرك قواعد ذكي يستعمل نظام التبادل الغذائي ADA ومعادلة Harris-Benedict.

**قاعدة بيانات الأطعمة** — كل طعام له حقل `meal` يحدد السياق:
```
meal: 'B' = فطور فقط    (زبدة، عسل)
meal: 'L' = غداء فقط    (زيت زيتون، أرز، كسكسي)
meal: 'BS' = فطور+وجبة خفيفة   (مكسرات)
meal: 'LD' = غداء+عشاء  (دجاج مشوي، خضروات)
meal: 'BSD' = كل الوجبات (توست، جبن)
```

**الدوال الرئيسية:**
| الدالة | الوصف |
|---|---|
| `calcBMR(gender, weight, height, age)` | معادلة Harris-Benedict |
| `calcTDEE(bmr, activityKey)` | السعرات اليومية الإجمالية |
| `calcTarget(tdee, goalKey)` | السعرات المستهدفة (min 1200) |
| `calcExchanges(target, goalKey, avoided)` | توزيع وحدات التبادل |
| `generateMenu(ex, mealCount, preferred, avoided)` | بناء قائمة الوجبات |
| `calcIdealWeight(height)` | الوزن المثالي (BMI 18.5–24.9) |
| `isGroupAvoided(groupKey, avoided)` | كشف منع مجموعة غذائية كاملة |

**منطق توليد الفطور:**
- نشويات: يُفضّل التوست/الخبز
- بروتين: يُفضّل الجبن/البيض
- دهون: **تُوزّع على 3 عناصر منفصلة** (زبدة + عسل + لوز) وليس عنصراً واحداً

**منطق الغداء:**
- نشويات: أرز/بطاطا/كسكسي
- بروتين: دجاج/لحم/سمك
- دهون: زيت زيتون فقط (يُمنع من الظهور في الفطور)

### API Route — `app/api/ai-plan/route.js`

```
POST /api/ai-plan
Body: { name, age, weight, height, gender, activity, goal, preferred, avoided, notes, meals }
Response: { bmr, tdee, target, ex, menu, form, date, ai: true/false }
```

**منطق التشغيل:**
1. إذا لم يوجد `ANTHROPIC_API_KEY` ← يستخدم المحرك المحلي مباشرة (مجاني)
2. إذا وُجد المفتاح ← يستدعي Claude (`claude-haiku-4-5-20251001`)
3. إذا فشل Claude لأي سبب ← يرجع للمحرك المحلي بصمت

**النموذج المستخدم:** `claude-haiku-4-5-20251001`  
**التكلفة التقريبية:** ~0.001$ لكل خطة (20x أرخص من Opus)

**التعليمات المرسلة للـ AI:**
- بيانات العميل الكاملة
- الأطعمة المفضلة والممنوعة
- **التعليمات الخاصة من المدرب** (`form.notes`) — جديد
- نظام ADA الكامل بقيم التبادل الدقيقة
- معادلة Harris-Benedict
- أنماط الوجبات التونسية

### صفحة الحاسبة — `app/dashboard/calculator/page.js`

**حقول الإدخال:**
| الحقل | الوصف |
|---|---|
| الاسم (اختياري) | اسم المشترك |
| العمر، الوزن، الطول | للحسابات |
| الجنس | ذكر/أنثى |
| مستوى النشاط | 5 مستويات |
| الهدف | خسارة/حفاظ/بناء |
| الأطعمة المفضلة | تُدرج بأولوية |
| الأطعمة الممنوعة | تُحذف كلياً إذا كانت مجموعة |
| 🤖 تعليمات خاصة للـ AI | ملاحظات طبية/تفضيلات خاصة — **جديد** |
| عدد الوجبات | 3 أو 4 أو 5 |

**قسم النتائج:**
- Step 1: BMR + TDEE + السعرات المستهدفة + **الوزن المثالي** (جديد)
- Step 2: جدول وحدات التبادل الغذائي
- Step 3: توزيع الوجبات (ملخص)
- Step 4: القائمة التفصيلية بالجرام
- زر تصدير PDF

**مؤشر الوزن المثالي (جديد):**
```
⚖️ الوزن المثالي (BMI 18.5–24.9): 65 – 87 كغ
[↑ الوزن الحالي أعلى بـ 10 كغ] / [✅ في النطاق المثالي] / [↓ ...]
```

**أقسام التقرير:**
